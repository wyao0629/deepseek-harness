# DSH 调度监控与等待

[English](README.md) | 中文

将调度命令交给独立 systemd 服务，托管作业运行时在标准 DSH 下一次模型请求之前阻塞等待。服务器每 5 秒读取状态，不调用模型；完成、失败、取消、中断或超时才通知 Agent。依赖 Linux、systemd，以及当前 harness 账号已有的 sudo 服务启动权限。

工具：`task_monitor_start(command, cwd?, timeout_seconds?)` 启动，`task_monitor_status()` 查询，`task_monitor_cancel(job_id)` 取消。默认最长 24 小时，最多 7 天。作业使用 harness 账号，需在命令里显式加载项目环境文件，不继承 DSH 模型凭证。状态和日志在 `~/.dsh/task-monitor/<job-id>/`。

DSH 的停止按钮只停止 Agent 等待，不终止后台作业。需要取消作业时，先点停止，再发送取消指令。作业完成仍会唤醒会话。DSH 重启不停止作业；整机重启则标记中断，不自动重跑 ETL。通知写入会话并确认持久化之后才确认交付；重启后未消费的队列通知会恢复唤醒。退出码 0 不等于业务入库完整。

仅约束新工具登记的作业和标准 DSH 模型步骤。直接 Bash 后台任务、原生 CLI 内部循环不受拦截。尚不支持通用的业务停滞识别，以配置的最长运行时间判断超时。状态可用工具查询，也能从 systemd/Cockpit 查看；此版没有独立实时看板。

验证命令：`node --test test/*.test.mjs`。部署验收仅使用“功能测试”工作区，不修改模型设置。卸载插件只停止监控，独立作业继续运行；如需停止，应先显式取消作业。

插件通过 DSH 原生运行时上下文注入中文使用指引；已有和新会话在下一次模型请求时获取，快照由 DSH 记录与管理。指引覆盖自然语言调度意图、执行前准备、启动、真正等待、查询、取消及完成后验收；不是每轮追加聊天消息，也不单凭关键词强制执行命令。
