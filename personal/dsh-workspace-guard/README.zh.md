# DSH 工作区删除检查

[English](README.md) | 中文

## 范围

这个可选的个人插件在 DSH 工具执行链路中，对识别出的文件删除调用请求授权。普通开发调用不提问。它使用现有执行身份，不修改模型设置或原生 Harness 适配器。

## 使用

已部署的 Web Profile 将本目录解析为 `dsh-workspace-guard`，并挂载 `cordis.patch.yml` 中的 `workspace-delete-guard` 条目。随附的 `policy.json` 要求逐次授权。本次通过 Profile 的 node_modules 符号链接和实时补丁部署，没有重启服务。以后安装时仍需挂载条目：仅拉取仓库不会自动启用。

识别到删除后，提问展示完整工具参数和工作目录。选择明确的允许选项授权本次调用，或者拒绝。授权绑定本次调用及其参数，不扩展为整个会话。本版本不会自动把自然语言许可转换成授权；用户需要回答专用问题。超出完整展示长度的调用需要拆分。

配置无法读取或损坏、提问服务不可用、取消操作或参数发生变化时，识别出的删除被拒绝。最终检查防止后续执行前监听器覆盖拒绝结果。它不能防止统一账号卸载插件或修改插件源码。

## 验证证据

七项 Node 测试覆盖配置缺失时的普通操作、异常拒绝、明确授权、参数变化、取消和已知删除模式。服务器标准预设验收会话执行 `rm --version` 时，界面出现等待回答状态；随后取消测试，没有删除文件。浏览器自动化超时，尚未完成界面允许和拒绝的全流程验收。授权后执行由自动化测试覆盖，不宣称已经完成浏览器验收。

## 限制与暂缓事项

检测识别直接删除工具名、补丁删除文件、常见 Shell 清理命令和部分内联脚本调用。它不是 Shell 解析器或操作系统隔离边界。别名、编码命令、外部脚本及其他工具的破坏行为可能漏检；文本匹配也可能对版本查询等无害命令请求授权。写入提及删除命令的文档不会因此被拦截。

本次不认证原生 Codex、Kimi、Grok Build 和 Claude 的执行路径。现有 Kimi 适配器在免提问策略下可能自动批准原生请求。接入暂缓期间，日常工作使用 DSH 标准原生模式。完整目录落位约束、复用用户明确指令的授权机制和完整上下文规则注入，也尚未在本插件中实现。

后续需要逐个确认原生执行前接口，在原生自动批准之前应用统一策略，将授权绑定准确操作，分别覆盖子 Agent 和直接 CLI 使用，并验证拒绝、取消、断线及重启。不能仅凭出现审批按钮认定已经覆盖。

## 运行记录

会话写入 `workspace-guard/decision` 事件，包含工具名、调用编号、决定原因和输入摘要哈希；插件不在这些事件中重复保存原始参数。DSH 自身的工具历史仍可能保存参数。检查异常写入不含敏感内容的服务器警告。验收文件和唯一的小型 Profile 备份位于功能测试工作区，按项目和日期归档。
