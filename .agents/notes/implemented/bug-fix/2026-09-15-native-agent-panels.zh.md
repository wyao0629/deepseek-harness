# Agent Note: 原生子 Agent 独立轨迹

Status: implemented

[English](2026-09-15-native-agent-panels.md) | 中文

## Problem

Kimi 活动展示丢弃子 Agent 文本增量，只显示汇总数量，完成后又被收进轮次过程折叠区。只保存在原生轨迹中的子 Agent 思考也未显示。Codex 协作调用以原始工具详情展示，开始和完成阶段重复列出。

## Decision

按原生 Agent、轮次和步骤归并 Kimi 事件。分别展示每个子 Agent 的任务、可折叠思考和独立输出，并显示实际派出、执行中、完成、失败/取消和等待数量。完成时一次性读取各自的原生轨迹，替换流式部分文本。只有明确属于主 Agent 的增量才能进入主回复。完成卡片定位到已关闭轮次的边界，使数量保持可见。

按接收方会话归并 Codex 协作状态和消息，并按工具调用 ID 去重生命周期阶段。Codex 协作事件未提供完整子 Agent 思考，不得用主 Agent 思考替代。本次未适配 Grok ACP 子 Agent 思考流。

## Alternatives considered

轮询时重复发送完整子 Agent 轨迹会重新引入历史加载带宽问题。按照请求的集群规模计数，会错误表示模型没有实际调用派发工具的任务。因此保留真实身份，完成时只发送一次权威子 Agent 快照。

## Consequences

已有 Kimi 事件历史可恢复独立的子 Agent 流式输出。完整的持久化子 Agent 思考由新版宿主完成的新任务保证，不自动回填所有历史任务。读取子 Agent 快照失败不会使已完成的主任务失败，诊断事件保留具体错误。开启集群模式不等于已经派出子 Agent。

验证包括 Kimi 单元测试、交错事件及快照替换测试、Codex 协作投影测试、功能测试工作区的真实双子 Agent 任务，以及刷新浏览器后两个独立结果和非折叠计数的检查。触发本次反馈的原生任务包含 85 个主 Agent 步骤，实际派出数量为零。
