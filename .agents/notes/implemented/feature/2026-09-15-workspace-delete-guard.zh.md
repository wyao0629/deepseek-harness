# Agent Note: 工作区删除授权

Status: implemented

[English](2026-09-15-workspace-delete-guard.md) | 中文

## 问题

现有 Hook 桥接器可能在检查失败后继续执行，且没有挂载工作区删除策略。用户希望保持统一身份和日常工作的便利。

## 决策

通过独立个人插件接入 DSH 工具执行前和最终检查接口。保留统一执行身份。只对识别出的删除调用提问，检查异常时拒绝，不将逐次授权转换为整个会话授权。不修改现有兼容 Hook 组件。

## 验证

七项针对性测试通过。功能测试工作区的标准预设会话执行无害的 `rm --version` 探针时，浏览器出现等待回答状态。随后取消测试，没有删除文件。浏览器自动化超时，因此界面完成路径仍未验证。通过实时 Profile 补丁上线，保留专门的小型备份，没有重启 DSH。

## 暂缓工作

原生 Harness 执行可能绕过 DSH 工具。Kimi 当前在免提问策略下会自动批准原生请求。Codex、Kimi、Grok Build 和 Claude 均需逐个接入执行前检查，并完成子 Agent 和直接 CLI 验收，才能宣称覆盖。不能通过更改界面标签消除这个限制。目录落位约束和自然语言授权复用需要单独实现；本次交付的检测器不是沙箱。

## 考虑过的替代方案

用户明确暂缓所有原生 Harness 的接入。修改共享桥接器会影响无关 Hook；独立插件可以限定改动范围。

## 影响

识别出的删除遇到异常会暂停，普通调用继续执行。覆盖范围明确限定在 DSH 工具链路。

## 交接

准确行为、异常处理和后续清单见[插件文档](../../../../personal/dsh-workspace-guard/README.zh.md)。保留用户统一身份的偏好，普通开发操作不增加审批弹窗。不推送密钥或原始会话日志。
